## 真实问题与人工检查

问题集位于 `tests/eval/live_research_questions.json`，13 类包含问候、报价、INTC 四维、季度催化追问、技术、财报影响、比较、宏观、港股、A 股、AAOI 新闻和两类报告。INTC/AAOI 标记为用户原问法，其余为策划验收用例。执行器 `scripts/live_research_eval.py` 保存实际答案、终态、质量、恢复结果与耗时；非空文本和 HTTP 200 不代表内容完整。

真实 HTTP 隔离库验收覆盖已完成样本的 `done.persistence_status=saved` 和 GET run 恢复一致性。第二批完成的比较、宏观、港股、A 股、新闻、单股报告均无交付合同错误，但部分回答为 `partial`，报告存在质量阻断；没有将这些记录写成完整内容通过。

验收发现并修复：腾讯名称扩出 ADR；同报道跨主体来源 ID 碰撞；搜索全文、失败字符串和结构体进入正文；比较重复；未知/旧闻被当当前事件；权威媒体补充支路丢质量标签；无情绪样本被称中性。保存的真实输入用于离线回放和对应 fixture，避免为纯渲染修复重复收费。

INTC 回放的聊天正文约 2332 字、brief 约 1505 字，37 条完整证据保留；比较聊天约 5515 字，42 条证据保留；宏观约 1117 字，13 条证据保留。后续新闻标签与缺口去重可能改变字数，验收不以字数为质量指标。

港股修复后本机复测为单一 `0700.HK`、`warn/partial`，不再出现 `evidence_id_content_conflict`；缺少报价、估值或官方公告仍明确标注。新闻展示保留出处与观点/旧闻/线索标签，不能因为缺少当前合格事件就输出假事件。

剩余报告验收改在开发机执行，使用生产数据供应商配置及系统 Step 5 Preview，凭据只进入内存和子进程环境，不复制业务数据库或认证私钥。该层验证真实取数、合成和质量门禁，不冒充 HTTP 持久化或生产语义 RAG 验收。最终结果在发布记录追加。

发布前追加回放修复两处合同问题：任务的 9 类明确义务曾被可选 Collector 输入扩成 13 类；同一 FRED/市场情绪来源被误绑定到不同股票及 Agent 抓取时间。修复后错误的期权/表现比较缺口消失，比较报告拒绝证据、身份冲突、结构错误均为 0，真实缺少必需材料仍阻断。对应定向主组 83 项及追加 4 项通过。

验收环境也有一项明确修正：开发机 `.venv` 原先未安装仓库已锁定的 `exa-py==2.13.0`、`tavily-python==0.7.21` 和 `ddgs==9.6.1`。这导致该阶段的本机报告搜索全部失败，不能归因为生产搜索源故障。已只在项目虚拟环境补齐依赖；依赖修复前的两份本机报告仅用于负路径和合同回放，不能作为完整报告成功验收。后续结果单独追加，不覆盖旧记录。

## 资源事故与验收位置调整

约 3.32 GiB 的生产宿主与其他业务共用。750 MiB QA 容器仍挤占了剩余内存；出现 swap 耗尽、SSH 握手超时和 Cloudflare 1033，直连和本机代理均失败。用户重启后站点 `/readyz` 恢复 200。

已保存 QA 回答与必要检查点，清理本次 QA 容器、隔离数据库及角色，未停止或删除其他业务。剩余完整验收移到开发机。发布脚本增加宿主可用内存与残留 QA 检查；BGE 在私网 worker 首次加载前检查内存，资源不足明确 `resource_limited`，主 API 保留持久词法检索。
