## 根因与下一步动作

### 1. 先修请求编译合同，完成后再处理证据质量

**已证实的原因：** [ticker_mapping.py](../../../backend/config/ticker_mapping.py) 的英文代码提取正则要求 2–5 个字母，漏掉 V；`COMMON_WORDS` 中包含 COST，优先被过滤；中文别名匹配会把显式 9988.HK 再扩成 BABA；BTC 的名称映射和标准交易对也未归一。h04 中的否定短语仍被 [intent_contract.py](../../../backend/graph/intent_contract.py) 召回为正向 facet。[request_frame.py](../../../backend/graph/request_frame.py) 的时间规则只覆盖部分“未来一个季度”表述，没有传递明确 90 天或 72 小时。

**动作：** 让统一请求合同显式保存主体及资产类型、任务与主体绑定、肯定/排除维度、时间窗口和澄清/直答/研究路线。明确代码优先于公司名称，采用同发行人和上市代码消歧；不能靠扩充普通词黑名单处理证券代码。缺标的进入澄清，概念题直接回答。复杂语义可由一次结构化解析产生候选，确定性规则负责校验；下游不得再次从完整问句猜任务。

**验收：** 单字母和普通词证券代码、港美双上市、加密资产、否定任务、72h/90d、空主语、概念题均有独立输入/合同断言；不调用行情就能验证编译正确。修复前冻结的本批保留首次分数，修后只作为回归集。

### 2. 收紧事实与解释的接口，补齐实际材料

**已证实的原因：** [research_synthesis.py](../../../backend/graph/synthesis/research_synthesis.py) 对模型自由选择的证据 ID 进行校验，多次失败并回退；未超时的模型回答也因此丢失解释。[analyze.py](../../../backend/graph/nodes/analyze.py) 仍以顶层 operation 决定是否需要研究分析；`valuation_sanity`、部分宏观任务或第一个子任务为 fetch 的混合请求会走确定性路径，无法完成比较和机制解释。公司档案和 SEC 索引存在，不代表业务、竞争内容已读到。

**动作：** 每个任务只向模型提供本任务允许的事实/论据 ID 与紧凑证据，结构化选择可用有限枚举或局部编号后由服务端映射；不取消真实性校验。局部引用无效时保留其余合法解释，并可做一次带错误原因的修正。按每个任务的解释要求决定是否调用分析模型，避免只看第一个 operation。业务/竞争需要实际披露正文，财报影响需要发布时间附近行情，估值/FCF 对比需要双方可比财期，新闻需要请求窗口和事件级去重。

**验收：** 同一事实的来源、期间、币种和 ID 从采集到渲染不丢；缺一维可见且只影响该维，不把公告目录充作业务结论，不把单家公司资料当成双方比较；引用失败与数据源失败分别计数。

### 3. 把“完整”绑定到用户要求，再校准报告展示

**已证实的原因：** ADBE 少了盘后属性仍显示已回答；多个案例的 `missing_requirements` 为空而人工需求明显未完成。IBM 只要引用块达标就显示 coverage=1.0，缺总判断却出现中性和固定精度标签。

**动作：** 从原始请求保留逐项验收义务，最终对实际正文检查：是否回答、是否有证据、是否遵守否定和时间范围。分别表示运行结束、回答完整度、证据覆盖和报告可发布性。证据不足应显示无法判断；没有校准依据不显示方向性置信度。报告业务/财务重复内容去重，默认收起执行诊断和来源长列表，保证结论及未答项先可见。

**验收：** 任一必答项漏答不能显示完整；部分报告可以保存和回看，但状态必须一致。使用同一真实账号再次验证刷新/历史/报告正文与质量标记一致，然后另冻一批新题复测。

### 4. 最后处理可定位的性能成本

维持已授权的模型预算，先删除错误召回导致的额外工具与重复上下文。把采集、RAG、合成、持久化、恢复 GET 的耗时分别记录，定位 IBM 正文出现后的约 16 秒尾延迟。Cloudflare 向量 API 兜底作为资源恢复事项继续推进，但它不能修复本批已证实的 V/COST 识别、否定失效和概念题误路由。

下一轮发布前，必须先通过合同回归和真实账号交付检查，再用新冻结问题做质量验收。若上游数据不足，接受明确 partial；不能为提高通过率而缩分母、放宽真实性门禁或隐藏失败。
