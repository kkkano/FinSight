## 1. 先给结论：重构重点不是继续加 Agent

当前 FinSight 已经拥有聊天、报告、行情、新闻、技术面、基本面、风险、RAG、调仓、提醒、回测和执行追踪等大量能力。真正拖累项目的原因，是三个基础契约同时存在并互相绕过：身份/租户契约、请求理解契约、报告质量契约。结果是同一个请求可能经过 `operation`、`request_frame`、`intent_contract`、`understanding_v2` 和 `reply_contract` 多次投影；同一份结果又会被同步 Chat、SSE execution、report index、cache 和前端恢复逻辑分别处理。

因此本方案选择“先收口边界，再迁移能力”的路线。最终运行链只有一条：

```text
RequestPrincipal
  -> RequestFrame
  -> PolicyDecision
  -> PlanIR(DAG)
  -> RunExecutor
  -> EvidenceLedger
  -> QualityGate
  -> Report/Answer Artifact
  -> EventStream + Persistence
```

前端也从“技术控制台”改为五个用户任务区：`今日 Today`、`问一问 Ask`、`研究 Research`、`组合 Portfolio`、`资料库 Library`；RAG Inspector、Cost Audit、原始 Trace、模型 Endpoint 和实验面板统一放入受角色保护的 `/ops/*`。

## 2. 邮件观点提取：哪些是决策，哪些仍是假设

邮件明确表达的产品方向是：作者是没有系统金融背景的普通程序员，主要需要搜索、整理、初步分析和直观解释；希望系统记住关注点、偏好和过去的判断；希望重要信息主动来到面前，但不希望被无关通知打扰；聊天用于追问和深入理解；系统是辅助研究工具，不做量化交易，也不代替用户决策。作者对多 Agent 协作和更高自主性有兴趣，但同时承认其收益没有被验证，且预算、时间和 token 有限。

据此，本计划做出以下产品决策：

1. **价值排序**：相关信息的发现、整理、解释、来源核验和历史复盘，高于 Agent 数量、图表数量和终端式信息密度。
2. **交互排序**：主动摘要/事件卡片是入口，聊天是追问入口，研究报告是可归档产物；不能要求用户每次先写一个复杂 prompt。
3. **表达排序**：默认显示“发生了什么、为什么与你有关、支持与反对证据、风险和下一步”，专业指标放进可展开层，并在首次出现时解释术语。
4. **记忆排序**：用户级关注、持仓、偏好和判断与线程级消息、选择、运行严格分离；记忆可查看、修改、暂停、删除和导出。
5. **Agent 排序**：简单事实查询走确定性检索或单 Agent；跨来源研究、观点复盘和冲突审查才升级为多 Agent。多 Agent 必须用质量、延迟、成本和用户评分证明价值。

以下仍是待验证假设，不能直接当作市场事实：多数用户是否需要主动摘要、是否愿意长期保存判断、Markdown 是否是最佳记忆呈现方式、多 Agent 是否值得额外成本，以及同时覆盖美股和中港股是否适合首版。每项都安排了实验，不把偏好直接硬编码成不可逆架构。

## 4. 目标产品与用户流程

首版默认用户是“有投资兴趣但不熟悉金融术语、每天只有几分钟查看时间的人”。登录后不再先看到技术宣传，而是看到：

```text
今日发生了什么
  -> 哪些内容与你的关注/持仓有关
  -> 依据和时间点是什么
  -> 哪些事实支持或削弱当前解释
  -> 你可以继续问什么、保存什么或静音什么
```

核心流程如下：

1. 用户首次进入：选择 1–5 个关注对象或主题，选择“简短解释/详细研究”偏好，明确通知频率。
2. Today 自动读取最近日报和事件卡片；没有数据时显示可解释空状态，不要求先点“生成”。
3. 卡片默认只展示摘要、关联原因、风险、来源和截至时间；点击“为什么”打开 EvidenceDrawer；点击预设问题进入 Ask，并自动携带 `event_id`、`source_ids` 和 `thread_id`。
4. Ask 统一处理主聊天和 MiniChat。简单问题使用短路径；需要当前数据或多来源证据时创建 Run，并实时显示阶段、数据状态和可取消操作。
5. Research 归档研究问题、证据账本、正反观点和版本化报告；报告质量不足时显示“预览/证据缺口”，不能伪装成已发布结论。
6. 用户可把一句话保存为自己的判断，设置复查时间或触发条件；新证据只生成“支持/削弱/无法判断”的复盘事件，不覆盖旧观点。
7. Portfolio 管理用户级持仓、自选、风险和规则；切换线程不改变这些数据。

```text
ThreadScope:    thread_id, user_id, messages, selections, current_subject
RunScope:       run_id, thread_id, status, events, artifacts, cancellation, deadline
```

新增 `backend/application/auth/principal.py` 和 `backend/application/context.py`，提供 `RequestPrincipal`、`require_principal()`、`require_thread_owner()`。所有 router 只从认证依赖拿 user/tenant，不再相信 body/query 的 `user_id`；客户端传来的旧 `session_id` 只能作为迁移 selector，必须与 principal 交叉校验。匿名模式只允许显式的临时 sandbox 数据，禁止读取或写入真实用户资源。

### 5.2 Postgres 单一业务数据平面

新增迁移目录（例如 `backend/db/migrations/`），目标表至少包括：

```sql
users(id, tenant_id, auth_subject, locale, created_at)
threads(id, user_id, title, current_subject, version, created_at, updated_at)
messages(id, thread_id, role, content, metadata_json, created_at)
runs(id, thread_id, user_id, request_hash, status, deadline_at, created_at, finished_at)
run_events(run_id, seq_no, type, stage, payload_json, created_at)
evidence_sources(id, run_id, source_url, source_type, published_at, retrieved_at, fingerprint, metadata_json)
claims(id, run_id, claim_text, claim_type, source_ids, confidence, quality_state)
reports(id, run_id, user_id, version, quality_state, publication_state, artifact_json)
watchlists(id, user_id, symbol, priority, enabled)
portfolio_positions(id, user_id, symbol, quantity, cost_basis, as_of)
monitor_rules(id, user_id, rule_json, quiet_hours, enabled)
notifications(id, user_id, event_id, severity, delivery_state, read_at)
memory_items(id, user_id, kind, content_json, source_run_id, state, updated_at)
outbox(id, aggregate_type, aggregate_id, event_type, payload_json, published_at)
```

开启 RLS 或等价 repository 强制条件：每个查询必须带 `tenant_id` 和 `user_id`。JSON/SQLite 迁移采用“快照备份 → 双读 → 用户确认/校验 → 用户级写入 → 切读 → 只读保留 → sunset”八步，不做不可逆覆盖。每个旧 `session_id` 记录映射表，无法确定归属的数据进入隔离的迁移待处理区，不猜测归属。

### 5.3 Canonical RequestFrame 与 PlanIR

新增 `backend/application/contracts/`，用 Pydantic 定义唯一写模型：

```python
class RequestFrame(BaseModel):
    request_id: UUID
    user_id: UUID
    thread_id: UUID
    query: str
    subjects: list[SubjectRef]
    facets: list[Facet]
    time_scope: TimeScope | None = None
    required_evidence: list[EvidenceObligation]
    render_intent: RenderIntent

class PlanStep(BaseModel):
    id: str
    kind: Literal["tool", "agent", "compute"]
    capability: str
    depends_on: list[str] = []
    required: bool = False
    timeout_ms: int
    retry_budget: int = 0

class PlanIR(BaseModel):
    version: Literal["1"] = "1"
    execution_mode: Literal["deterministic", "research", "deep_research"]
    steps: list[PlanStep]
    deadline_ms: int
```

`operation`、`understanding_v2` 和旧 `request_frame` 只在 `backend/adapters/legacy_projection.py` 读写，主图不再直接读取。旧 API `/chat/supervisor`、`/chat/supervisor/stream`、`/api/execute` 保留兼容适配，新增 `/api/v2/runs` 和版本化 SSE；迁移期间对同一请求做 shadow compare，记录 canonical 与 legacy 的路由差异，连续两周无高优先级差异后删除投影。

### 5.4 单一 Capability Registry

把 `backend/tools/manifest.py`、`backend/langchain_tools.py`、Agent capability registry 和 UI capability endpoint 收口为 `backend/application/capabilities/registry.py`。每个 `ToolSpec/AgentSpec` 同时描述名称、输入输出 schema、市场、证据类型、权限、风险、超时、缓存、所需环境变量和 invoker。Policy、Planner、Executor、设置页和诊断页全部从同一 registry 生成。

执行器只接受 registry 中的 capability；缺失 invoker 或必需环境变量时返回 `failed/configuration_missing`，不能退化成带 summary 的成功。Planner 只输出 DAG，不再负责执行策略；Policy 只验证权限、预算和 required evidence，不再复制一套工具选择 if/else。

### 5.5 统一 RunService、重试、取消和质量门

新增 `backend/application/runs/run_service.py`，提供：

```text
start(request, principal) -> RunHandle
stream(run_id) -> AsyncIterator[RunEvent]
resume(run_id, confirmation) -> RunHandle
cancel(run_id, principal) -> None
```

同步 Chat 和 SSE 都调用同一个 RunService；report build、quality、index、memory projection 只能在这里执行一次。每个 Run 生成一个绝对 deadline，所有 Agent、工具、LLM retry 从剩余时间计算预算；删除 `llm_retry` 的默认 3600 秒等待，重试次数、退避和取消令牌由 RunService 统一注入。

Agent 结果改为：

```json
{
  "status": "success|degraded|failed|cancelled",
  "evidence_ids": [],
  "claims": [],
  "failure_code": null,
  "retry_used": 0,
  "latency_ms": 0
}
```

`degraded` 可以继续生成“证据缺口”答案，但不能被 renderer 变成 `success`；required step 失败直接阻止正式报告，只允许生成明确标记的 preview。

质量门拆为：

- `execution_status`: running/success/degraded/failed/cancelled。
- `quality_state`: pass/warn/block/unknown。
- `publication_state`: unpublished/preview/published/withdrawn。

只有 `quality_state=pass|warn` 且满足 publication policy 的 artifact 才进入默认索引和 cache；`block` 永不写默认 report index/cache。缓存键至少包含 `tenant/user`、request hash、time scope、data cutoff、evidence fingerprint、policy version、prompt version 和 locale。

### 5.6 RAG 与 Observability 解耦

保留 `memory/ws/kb` 三层语义，但把实现拆成：`EvidenceIngestService`、`PromotionPolicy`、`RetrievalService`、`ObservabilitySink`。Executor 只产出 EvidenceIR；outbox worker 异步写 source/chunk/vector/observability，避免在 `execute_plan_stub.py:1442-1734` 中同步双写几十个对象。

生产 profile 禁止静默 memory fallback；启动 readiness 做真实 embedding encode probe，并报告 `backend_actual`、`embedding_actual`、`reranker_actual`。Postgres 或模型不可用时，返回明确 `degraded/rag_unavailable`，不把空检索当成功。KB 晋升默认只接受一手公告、监管文件、电话会等可信来源，其他来源需质量分和去重后进入待审核队列。

### 5.7 调度与部署

FastAPI lifespan 只初始化 Web 依赖，不创建扫描和发信 scheduler。新增 worker 进程（可先用同仓库 `python -m backend.worker`，后续再换队列实现），任务表使用幂等 key、lease、重试和 Postgres advisory lock。邮件、日报、监控、RAG retention 由 worker 执行，API 只提交任务和读取状态。

拆分依赖：`requirements-runtime.txt`、`requirements-dev.txt`、`requirements-eval.txt`，锁定主要版本；生产镜像不安装 pytest、RAGAS、浏览器和完整训练依赖。Compose 默认前端使用同源 `/api` 代理，生产远程域名必须显式传 `VITE_API_BASE_URL`；后端端口默认只在内部网络暴露。增加 `/livez`、`/readyz`：readiness 必须包含 LLM 配置、数据库、checkpoint、RAG backend 和必要 capability 状态。

## 6. 目标前端架构与具体实现

### 6.1 目录和状态边界

```text
frontend/src/
  app/                 # router/providers/guards
  features/
    today/             # digest/findings/notification feedback
    ask/               # composer/chat/thread
    research/          # subject workspace/report/evidence
    portfolio/         # holdings/risk/monitor
    library/           # reports/decision journal/memory
    ops/               # inspector/cost/raw trace
  entities/            # user/thread/run/evidence/ticker
  shared/
    api/               # typed domain clients
    query/             # dedupe/cache/invalidation

    ui/                # tokens/components/resource states
```

Zustand 只保存 UI 意图（当前路由、选中对象、composer 草稿、显示设置）；远端资源交给 TanStack Query 或等价自建 query cache。每一个 query key 必须包含资源、用户、参数和版本；统一 stale time、abort、重连、旧数据保留和错误重试。

### 6.2 唯一 ResearchRunController

从 `ChatInput.tsx` 和 `MiniChat.tsx` 提取 `useResearchRunController`，职责包括发送、SSE 解析、run reducer、恢复、取消、重连、报告回放和 terminal state。两个组件只负责不同布局，不再复制网络生命周期。同一 `thread_id` 默认只允许一个活动 run；切换页面仍能观察同一个 run，停止操作带明确 `run_id`。

删除前端 `synthetic_done`；只有 `done|failed|cancelled|blocked` 等带 schema 版本的 terminal event 才能结束。无事件超时只显示“连接暂时无响应，正在确认状态”，随后调用 run status/replay API，不构造业务完成。

### 6.3 Today/Ask/Research/Portfolio/Library 信息架构

- Today：`TodayDigest`、`FindingCard`、`SinceLastVisit`、`PendingReview`。默认展开摘要，不把完整 Agent 日志放在首屏。
- Ask：统一会话列表、composer、上下文 pill 和运行状态；报告/证据通过抽屉或跳转 Research 展开。
- Research：按标的或主题显示摘要、时间线、财务/新闻/技术、证据、正反观点和版本化报告；桌面可有可收起侧栏，移动端一次只显示一个面板。
- Portfolio：持仓、风险解释、规则和通知；所有数据以 `user_id` 查询，不依赖当前 thread。
- Library：报告、收藏证据、判断日志、记忆控制。支持查看、编辑、暂停、删除、导出。
- Ops：只有管理员或开发角色可见；原始 trace、成本、endpoint 和 RAG DB 浏览器不得出现在普通侧栏。

### 6.4 设计系统和可访问性

以根目录 `DESIGN.md` 为决策源，把 `--fin-*`、`--bb-*` 和硬编码色值归并为 semantic tokens：surface、text、border、accent、positive、negative、warning、unknown、stale、blocked、evidence-quality。正文默认 14–16px，等宽字体只用于 ticker/价格/时间/诊断。修正 muted 对比度至普通文字 ≥4.5:1，触控目标 ≥44px。

重写 `Dialog.tsx`：Escape 关闭、焦点捕获、初始焦点、关闭后恢复、描述关联；重写 `Tabs.tsx`：`aria-controls`、tabpanel、roving focus、左右方向键；所有图表提供文字摘要和表格替代；动画尊重 `prefers-reduced-motion`。每个远端组件采用统一 `ResourceState<T>`：loading/ready/partial/empty/stale/degraded/error/blocked，并显示 source、as_of、fallback_reason 和下一步。

### 6.5 性能和依赖

在 `App.tsx` 使用 route-level lazy import；ECharts、Markdown、RAG Inspector、Cost Audit 独立 chunk。目标是 Today/Ask 初始业务 gzip ≤300KB，中端移动设备 LCP <2.5s、INP <200ms。移除根 `package.json` 与 frontend 重复依赖声明，统一 npm lock、Node 版本和 Tailwind/Vite 文档；逐项升级 23 个 audit 漏洞并用 build/unit/e2e 回归确认。

2. 组件：Today 卡片、EvidenceDrawer、Dialog、Tabs、状态组件、图表空/旧/降级状态。
3. E2E：登录/匿名边界、添加关注、Today→Ask、Ask→Research、保存判断、静音通知、切换三线程、取消/恢复 run、移动端导航。
4. 系统 E2E：真实 FastAPI + Postgres + Nginx 同源 smoke，不能全部依赖 `page.route().fulfill()`；mock E2E 继续保留用于快速 UI 回归。
5. 可访问性/性能：axe、键盘、屏幕阅读器语义、reduced motion、375/768/1024/1440 截图、LCP/INP、bundle size。

## 9. 风险、取舍与回滚

| 风险 | 原因 | 缓解与回滚 |
|---|---|---|
| 数据迁移错配 | 旧 session 同时承载用户和线程 | 先只读映射、生成差异报告；不确定记录进入待处理区；保留原文件快照。 |
| 认证切换阻断匿名体验 | 现有测试和本地用户依赖匿名 | 建立显式 sandbox tenant；生产资源只允许 principal；保留旧 API 但拒绝越权。 |
| 多 Agent 成本/延迟暴涨 | 当前多层 retry 和 DeepSearch 长尾 | 统一 deadline、预算和升级阈值；默认 simple path；失败返回可解释 degraded。 |
| Postgres 切换失败 | 当前大量代码直接操作 JSON/SQLite | repository adapter 双读；按表逐个切换；每次迁移有校验 SQL 和回滚开关。 |
| RAG 质量下降 | embedding/reranker 运行态不稳定 | encode probe、数据 cutoff、离线基线和 shadow compare；生产不静默 fallback。 |
| UI 重做引入回归 | 当前 E2E 多为 mock，覆盖不到真实链路 | 先保留旧 route adapter；新增真实同源 smoke；每个页面逐步切换。 |
| 依赖升级破坏构建 | 23 个 audit 漏洞且版本漂移 | 一次只升级一个直接依赖，锁文件审查，跑 lint/unit/build/E2E 后再合并。 |
| 过度重构拖延交付 | 范围覆盖前后端全部模块 | 每阶段有可独立上线的止血结果；两周无价值的实验能力移出主导航。 |

## 11. ADR：为什么选择渐进式领域重构

**Decision**：保留现有公开 API 和 LangGraph 外壳，新增 application ports、Canonical IR、RunService、Postgres repository、Capability Registry 和 Today-first 前端；通过双读/shadow compare/feature flag 分阶段切换，最后删除旧 projection、stub 和文件存储。

**Drivers**：身份隔离和数据正确性是 P0；用户需要主动、易懂、可追溯的研究体验；当前已有大量可复用工具和测试，全部重写会丢失已验证能力；个人预算要求每阶段都能得到可见价值。

**Alternatives considered**：

1. 继续在当前 LangGraph 上补丁：短期改动少，但会继续增加多套契约和 fallback，无法解决所有权、事务和前端双流问题。
2. 一次性重写为全新微服务/全新前端：边界干净，但迁移数据、行为和已有测试的风险最高，个人项目成本不可控。
3. 只做视觉改版：见效快，但会给错误的 session 归属、假完成和质量发布语义换一层皮，无法实现邮件中的个性化目标。

**Why chosen**：渐进路线允许先修越权和可信度，再迁移数据与契约；每一阶段都有可回滚边界，并能用现有 129 个后端聚焦测试、210 个前端单测和 37 个 E2E 作为回归基础。

**Consequences**：短期会同时维护 adapter 和 canonical path，代码量不会立即下降；需要严格记录 feature flag、数据映射和 shadow 差异。长期可以删除四个超大核心文件中的兼容分支，支持多 worker、多设备和真正的主动服务。

**Follow-ups**：确定首批市场范围和可信来源；确定 Postgres 托管/保留周期；完成多 Agent 对照评测；决定 Markdown 记忆是展示层还是持久化格式；在 Phase 0 结束前确认产品默认通知等级。

## 12. 最终验收清单（完成定义）

- [ ] 同一用户创建、切换三条线程，持仓、自选、监控、通知和偏好一致；跨用户访问全部拒绝。
- [ ] 所有 Run 都有唯一 `run_id`、明确 deadline、可取消；terminal event 恰好一次，前端不合成 done。
- [ ] 关键结论 100% 可定位来源、发布时间、抓取时间和 evidence/quality 状态；blocked 不进入默认发布索引或缓存。
- [ ] 简单问题不强制启动多 Agent；复杂研究记录每个 Agent 的职责、证据、预算和失败语义。
- [ ] 生产 LLM、数据库、RAG、embedding、reranker 状态进入 readiness；故障显式 degraded/failed，不静默丢数据。
- [ ] Today 首屏在无输入时仍能展示个性化摘要或可解释空状态；新用户 60 秒内完成首次关注和追问。
- [ ] 一级导航不超过五项，Ops 与原始 trace 角色隔离；普通用户不需要理解 LangGraph、RAG 或 Agent 才能完成任务。
- [ ] 所有远端模块覆盖 loading/ready/partial/empty/stale/degraded/error/blocked；所有按钮有 pending/success/failure/retry。
- [ ] WCAG 2.2 AA 关键指标通过：普通文本 ≥4.5:1、目标 ≥44px、Dialog/Tabs 键盘闭环、axe critical/serious=0。
- [ ] 初始业务 gzip ≤300KB、LCP <2.5s、INP <200ms；同一资源不会重复轮询。
- [ ] CI 执行完整后端 tests、coverage、前端 lint/unit/build/E2E/a11y/bundle budget、真实同源 smoke、Docker readiness；历史报告绑定当前 commit。
- [ ] 文档事实源同步：根 `DESIGN.md`、本计划、`docs/DOCS_INDEX.md`、README、Runbook、环境模板和 CI 路径一致。

达到上述清单前，不宣布“所有功能已修好”；达到后再决定是否扩展更多市场、更多 Agent 或更多主动渠道。
