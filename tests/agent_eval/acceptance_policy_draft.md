# 独立资源验收政策草稿

用户允许合理预算波动，并以回答质量为主要标准。当前默认 25% 只用于自动验收及复核参考，不更改已经执行的时间、token 或费用预算；该数字不是用户指定的精确值。

原始严格比较、完整原件及 SHA 始终保留。独立验收要求双方完整 60 题、相同题目身份/模型/资料/调度/独立评分，并只在深拷贝中调整有证据的运行完成率和模型失败率。题目分数、引用、产物、权限和单终态不改。

预算豁免须同时具备完整有效正文、独立 `answered=2` / `numbers=2`、无内部标识泄漏，以及引用、关键产物、权限和单终态合同满足。没有答复、仅有过程文字或关键要求缺失不能据预算取得通过。

预算归因仅使用结构化错误码和阶段终态。通用 `model_timeout`、只有 `review_failed` 的取消，或不能映射到具体轮次的取消保留为 `operational_uncertain`。HTTP/协议异常不能冒充预算失败。已确认阶段 deadline 或 review timeout 且位于同轮最后一次的取消，才可自动区分为内部资源中断。

token 按各轮记录的实际用量检查；现有报告没有各轮完整耗时时，时间只按 case 总耗时除以每轮预算与轮数的乘积检查，报告明确写 `case_aggregate_only`，不推定每轮均低于 25% 波动。

超过默认参考幅度、证据不足或只剩操作指标差异时输出 `needs_review`，表示不能自动接受，不表示已经判定答案质量失败。内容/数字/来源/关键交付真实退步和未知 HTTP/协议异常继续阻止自动接受。人工判读由 root 留下另行绑定证据，不回写原始分数。

入口为 `acceptance.evaluate_files(baseline_path, current_path)`；模块只读原件，输出原始严格比较、独立投影结果、原始/调整后计数、逐 case 归因、未决操作项与源文件 SHA。正式应用在全部独立评分完成之后。
